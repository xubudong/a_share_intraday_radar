# 股票池三级分类数据结构设计

## 目标

在不破坏现有股票星标、板块星标、研究笔记和历史快照的前提下，把当前基于分组名称的两层结构升级为：

`一级大板块 -> 二级产业环节 -> 三级细分赛道`

同时增加独立的主题标签，用于表达“先进封装、红利、国产替代、AI应用、固态电池、CPO”等跨行业逻辑。

界面需要同时展示一级、二级、三级行情统计，并支持任意层级筛选、星标、笔记和快照。

## 一、现有结构的问题

### 1. 名称同时承担ID和展示文案

当前板块星标、笔记、前端筛选和行情统计都直接使用中文分组名称。只要改名，已有状态就会失去关联。

实际数据中已经存在这种情况：板块星标仍保存旧名称 `电子元件-PCB`，而当前配置已经改为 `电子元件-PCB/FPC`。

### 2. 股票按分组重复配置

同一股票可以在多个分组重复出现。加载器以第一次出现的位置作为主分组，并把多个梯队取最小值，导致：

- 配置顺序决定主行业。
- 无法表达“在主赛道是T1，在相关赛道只是T2”。
- 名称、笔记和梯队可能在重复记录之间冲突。

### 3. 系统不理解真正的三级关系

`新能源-锂电材料-正极`目前只是一个完整字符串。系统不能直接统计“锂电材料”整体，也不能按父子节点自动汇总。

### 4. 历史数据直接保存旧分组名称

现有历史快照保存了 `group`、`groups` 和 `group_stats`。快照应保持不可变，不能为了新分类批量重写历史文件。

### 5. 用户状态存在多种自由文本

研究笔记中除了完整分组名，还存在 `PCB`、`光纤`、`工业气体`、`先进封装` 等自由scope，需要别名表辅助迁移。

## 二、核心设计原则

1. 行业节点使用稳定ASCII ID，中文名称只负责展示。
2. 股票只保留一条基础记录，通过行业成员关系表达主赛道和相关赛道。
3. 行业和主题标签分开建模。
4. 梯队属于“股票在某个赛道中的地位”，不能只存在股票全局字段。
5. 一级、二级统计从三级成员向上聚合，同一股票在同一父节点只计算一次。
6. 旧配置和旧API保留兼容投影，迁移期间不要求一次改完所有调用方。
7. 历史快照不改写，读取时通过别名表做显示兼容。

## 三、建议配置文件

### 1. `config/industry_taxonomy.yaml`

存放行业树、主题标签和旧名称别名，不存放股票。

```yaml
version: 1

industries:
  - id: semiconductor
    name: 半导体
    aliases:
      - 半导体芯片
      - 半导体材料
      - 半导体设备
      - 先进封装
    children:
      - id: semiconductor.materials
        name: 半导体材料
        children:
          - id: semiconductor.materials.electronic_gases
            name: 电子特气
            aliases:
              - 半导体材料-电子特气
              - 电子特气
          - id: semiconductor.materials.photoresist
            name: 光刻胶
            aliases:
              - 半导体材料-光刻胶
      - id: semiconductor.equipment
        name: 半导体设备
        children:
          - id: semiconductor.equipment.metrology
            name: 检测/量测
            aliases:
              - 半导体设备-检测/量测
      - id: semiconductor.packaging
        name: 封装测试
        children:
          - id: semiconductor.packaging.osat
            name: 封测厂
            aliases:
              - 先进封装-封测厂

tags:
  - id: advanced_packaging
    name: 先进封装
    aliases:
      - Chiplet
      - 2.5D/3D封装
  - id: dividend
    name: 红利
  - id: domestic_substitution
    name: 国产替代
```

约束：

- `id`发布后不随中文改名而变化。
- 一级ID使用单段，例如 `semiconductor`。
- 二、三级ID使用父级前缀，便于调试但不能依赖字符串切割判断父子关系。
- 父子关系以配置树为准。
- 每个旧分组至少映射到一个新节点或明确标记为待拆分。

### 2. `config/stock_pool.yaml`最终形态

股票从“按分组重复列出”改为“一只股票一条记录”。

```yaml
version: 2

stocks:
  - code: "688268"
    name: 华特气体
    memberships:
      - industry_id: semiconductor.materials.electronic_gases
        primary: true
        tier: 1
    tags:
      - domestic_substitution
    note: 半导体电子特气核心供应商

  - code: "603993"
    name: 洛阳钼业
    memberships:
      - industry_id: nonferrous.base_metals.copper
        primary: true
        tier: 1
      - industry_id: nonferrous.energy_metals.cobalt
        primary: false
        tier: 1
      - industry_id: nonferrous.minor_metals.molybdenum
        primary: false
        tier: 1
    tags:
      - resource_security
```

字段说明：

| 字段 | 含义 |
| --- | --- |
| `memberships` | 股票所属的三级行业节点列表 |
| `industry_id` | 稳定三级行业ID |
| `primary` | 是否为主行业，只允许一个 `true` |
| `tier` | 股票在该三级赛道中的梯队 |
| `tags` | 独立主题标签ID列表 |
| `note` | 个股主营和投资逻辑摘要，不代替证据核验 |

校验要求：

- 股票代码唯一。
- 股票简称唯一来源，禁止重复记录使用不同简称。
- 每只股票恰好一个主行业。
- 所有行业ID和标签ID必须存在于taxonomy。
- 梯队只能是1、2、3。
- 同一股票不能重复加入同一个行业节点。

## 四、运行时模型

建议把当前 `StockConfig` 扩展为：

```python
@dataclass(frozen=True)
class IndustryMembership:
    industry_id: str
    tier: int
    primary: bool = False


@dataclass(frozen=True)
class StockConfig:
    code: str
    name: str
    memberships: tuple[IndustryMembership, ...]
    tags: tuple[str, ...] = ()
    watch: bool = False
    note: str = ""
```

迁移期保留兼容属性：

- `group`：主行业三级节点的完整中文路径。
- `groups`：所有行业成员关系的完整中文路径。
- `tier`：主行业成员关系的梯队。

这些兼容字段由新模型计算生成，不再作为真实数据源。

## 五、统一scope设计

筛选、星标和笔记不再使用中文名称，而使用稳定scope键：

```text
all
industry:semiconductor
industry:semiconductor.materials
industry:semiconductor.materials.electronic_gases
tag:advanced_packaging
stock:688268
```

统一scope后，同一套接口可以支持一级、二级、三级、主题标签和个股笔记。

## 六、统计规则

### 1. 行业节点统计

- 三级节点：统计直接成员，包括主行业和相关赛道成员。
- 二级节点：统计所有子三级节点成员的并集。
- 一级节点：统计全部后代节点成员的并集。
- 同一股票在同一个汇总节点只计算一次。
- 涨跌幅口径先延续现有简单平均，同时展示上涨、下跌、平盘家数。
- 后续如增加市值加权，必须明确标注为另一项指标，不能悄悄替换现有口径。

### 2. 梯队显示

- 默认表格显示主行业梯队。
- 当用户筛选某个三级赛道时，显示该股票在当前赛道的梯队。
- 一级、二级筛选下，以主行业梯队排序；相关赛道成员可增加“相关”标识。

### 3. 标签统计

- 标签统计使用拥有该标签的股票集合。
- 标签和行业统计完全分开，防止“红利”再次成为行业。
- 第一版只支持单scope筛选；多标签组合筛选可以后续增加。

## 七、API建议

### 1. 新增taxonomy接口

`GET /api/taxonomy`

返回：

- 完整行业树。
- 标签列表。
- 每个节点的显示名称、父节点和层级。
- 当前用户星标状态。

### 2. dashboard返回scope统计

新增：

```json
{
  "scope_stats": {
    "industry:semiconductor": {
      "total": 42,
      "up": 28,
      "down": 12,
      "flat": 2,
      "avg_pct": 2.18,
      "star": true
    }
  }
}
```

迁移期继续返回旧 `group_stats`，直到历史快照和前端全部完成兼容。

### 3. 股票payload新增字段

```json
{
  "primary_industry_id": "semiconductor.materials.electronic_gases",
  "industry_memberships": [
    {
      "industry_id": "semiconductor.materials.electronic_gases",
      "tier": 1,
      "primary": true
    }
  ],
  "tags": ["domestic_substitution"]
}
```

同时保留 `group`、`groups`、`tier` 兼容字段。

### 4. 星标接口

新增 `POST /api/toggle-scope-star`，请求字段为 `scope_id`。

旧 `/api/toggle-group-star` 在迁移期继续保留，通过别名表把旧名称解析为新scope。

## 八、用户状态兼容

### 1. 板块星标

`star_state.json`升级为version 2：

```json
{
  "version": 2,
  "stars": [],
  "scope_stars": [
    "industry:semiconductor.materials.electronic_gases",
    "tag:advanced_packaging"
  ],
  "holdings": []
}
```

迁移规则：

- 旧 `groups`逐项通过aliases解析。
- 精确匹配的直接迁移到对应三级节点。
- 原分组需要拆分时，迁移到共同父级，避免丢失关注状态。
- 无法解析的旧星标保留在 `legacy_groups`，并记录警告，不静默删除。
- 写入前创建同目录备份，迁移过程可重复执行且结果一致。

### 2. 研究笔记

- `stock:代码`保持不变。
- `全部`迁移为 `all`。
- 完整旧分组通过aliases映射到行业scope。
- `PCB`、`光纤`、`有色`等自由scope使用单独的note alias表。
- 无法唯一映射的笔记保留原scope，并显示在“旧分类笔记”中。
- 不覆盖或合并同日期不同scope的内容。

### 3. 浏览器板块顺序

当前大板块顺序保存在localStorage。前端首次读取时：

- 把旧大板块名称映射到新一级行业ID。
- 多个旧板块合并到同一新板块时保留第一次出现的位置。
- 无法识别的名称忽略但不阻断页面。
- 使用新的storage key保存迁移结果，旧key暂不删除。

## 九、历史快照兼容

现有快照保持只读，不进行批量改写。

读取旧快照时：

1. 检查是否存在 `schema_version`。
2. 无版本或version 1时，使用分组aliases生成临时scope统计。
3. 混合分组无法准确拆分时，按旧统计原样展示，并标记“旧分类口径”。
4. 新快照写入：

```json
{
  "schema_version": 2,
  "taxonomy_version": 1,
  "scope_stats": {},
  "stocks": []
}
```

快照应保存当时的中文显示名称或taxonomy摘要，避免未来改名后无法还原历史界面。

## 十、舆情匹配兼容

- 匹配词同时包含行业名称、完整路径、aliases和标签名称。
- 命中结果新增 `matched_scopes`，使用稳定scope ID。
- 迁移期继续生成 `matched_groups`中文兼容字段。
- “先进封装”等词命中主题标签，不应把股票主行业改成先进封装。
- 个股只有在其配置中具备相应行业成员关系或标签时，才因该主题被自动关联。

## 十一、前端展示

一级板块作为最外层行情区域，内部按二级行业展示汇总卡，二级卡内平铺三级赛道：

```text
半导体 +2.18%  18涨/9跌

半导体材料 +3.26%  8涨/2跌
电子特气 +6.35%  光刻胶 +3.21%  CMP +2.18%

半导体设备 +2.47%  7涨/3跌
检测量测 +4.21%  前道设备 +2.86%  零部件 +1.73%
```

交互要求：

- 一级、二级、三级均可点击筛选。
- 一级、二级、三级和标签均支持星标。
- 二级内部三级赛道默认按当日涨跌幅排序，星标赛道优先。
- 表格分组列显示主行业路径，并可点击跳转到对应三级筛选。
- 相关赛道单独显示，不再与主行业混为一个字符串。
- 主题标签放在独立“关注主题”区域，不能混入行业树。

## 十二、两阶段实施顺序

### 阶段A：兼容层与三级看板

1. 新增 `industry_taxonomy.yaml`，录入已确认的行业树和123个旧分组aliases。
2. 新增taxonomy加载、校验和scope解析。
3. 继续读取现有group结构，通过aliases投影到三级行业节点。
4. 新增scope统计和taxonomy API，同时保留旧字段。
5. 前端切换为三级行情看板和scope筛选。
6. 增加星标、笔记、localStorage和旧快照兼容。

这一阶段不批量改写584只股票，目标是先完成结构和展示。

### 阶段B：逐股审计与stock_pool v2

1. 按一级行业逐批审计个股。
2. 每只股票确定主行业、相关赛道、赛道梯队和主题标签。
3. 排除只有互动回复、研发立项、送样而无收入、订单或量产证据的概念股。
4. 把通过核验的股票转换为version 2单记录结构。
5. 全量校验后移除旧group兼容配置，但API兼容字段可以继续保留一段时间。

## 十三、测试边界

至少覆盖：

- taxonomy节点ID、父子关系和别名唯一性。
- 123个旧分组全部可解析或被明确标记为待拆分。
- 一级、二级聚合对重复股票去重。
- 三级筛选能识别主行业和相关赛道。
- 当前赛道使用赛道自己的tier。
- 旧板块星标可迁移且不丢失未知值。
- 板块笔记、个股笔记和自由scope笔记兼容。
- version 1和version 2快照均能读取。
- 舆情匹配同时支持旧名称、行业别名和主题标签。
- 前端点击一级、二级、三级、表格分组和标签均能正确过滤。

## 十四、回滚策略

- 阶段A只新增taxonomy和兼容字段，不删除旧 `group/groups/group_stats`。
- 用户状态迁移前保留备份，写入失败时继续使用version 1数据。
- 新前端若异常，可恢复读取旧 `group_stats` 和旧分组按钮。
- 历史快照始终不改写，因此不需要快照回滚。
- 阶段B按一级行业分批迁移，每批单独验证和提交，避免一次性重写整个股票池。

## 十五、建议的首个实现批次

先以半导体作为试点：

- 层级完整，能覆盖一级、二级、三级统计。
- 同时包含先进封装等跨行业主题标签。
- 包含多赛道公司，能验证相关赛道和赛道级tier。
- 用户近期重点关注，最容易判断展示是否符合盘中使用习惯。

半导体试点通过后，再依次迁移AI算力、计算机、传媒互联网、煤炭、公用事业、电力设备、新能源、电子和通信。
